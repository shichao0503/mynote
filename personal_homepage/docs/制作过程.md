# 从 GitHub 仓库到个人主页：一步一步制作

制作日期：2026 年 10 月 21 日。目标仓库：`shichao0503/mynote`。

这份教程解释网站为什么能运行，以及你以后如何修改。具体执行结果和遇到的问题见[实操记录](实操记录.md)。

目录调整：个人主页、素材、预览脚本和教程现已统一放在 `personal_homepage/`。下文中的 `index.html`、`assets/`、`scripts/` 默认相对于这个文件夹；只有发布配置、Git 提交命令和根目录跳转页以仓库根目录为准。

## 1. 先理解三个角色

| 名称         | 在这个项目中做什么                                 |
| ------------ | -------------------------------------------------- |
| 网页文件     | 浏览器读取的 HTML、CSS、JavaScript 和图标          |
| GitHub 仓库  | 保存源码与修改历史，类似一个有版本记录的项目文件夹 |
| GitHub Pages | 把指定分支中的网页文件发布成可以访问的网站         |

本项目的关系是：

```text
在电脑修改文件 → 提交到 GitHub main 分支 → GitHub Pages 发布 → 浏览器访问
```

仓库地址和网站地址不是同一个东西：

- 仓库：<https://github.com/shichao0503/mynote>
- 网站：<https://shichao0503.github.io/mynote/personal_homepage/>

网站地址由用户名 `shichao0503`、仓库名 `mynote` 和目录名 `personal_homepage` 组成。网址末尾保留 `/`，有利于正确解析相对资源路径。旧地址 `/mynote/` 由根目录跳转页自动转到新地址。

## 2. 为什么这次没有用 Astro

你朋友的项目使用 Astro，先把源码构建为静态文件，再发布到 Pages。

你的第一版主要是一张个人介绍页面，直接用浏览器就能理解的文件即可：

| 文件               | 负责什么                         | 类比               |
| ------------------ | -------------------------------- | ------------------ |
| `index.html`       | 文字、内容顺序、链接、区块结构   | 房屋骨架与房间用途 |
| `assets/style.css` | 颜色、字体、尺寸、布局、手机适配 | 装修与摆放         |
| `assets/main.js`   | 点击复制邮箱、自动更新页脚年份   | 开关和小机关       |

因此这一版没有 `npm install`、没有 `npm run build`，也没有生成 `dist` 的步骤。网页源码本身就是发布文件。

这并不影响它使用 GitHub Pages，也不妨碍以后改成 Astro。当你要持续写很多 Markdown 笔记、复用页面布局或自动生成目录时，再引入框架会更有价值。

## 3. 把简历变成网页内容

不能把一份简历所有字段原样堆到首页。先确定读者需要了解什么：

1. 你是谁，关注什么方向。
2. 你能做哪些事情。
3. 工作经历如何支撑这些能力。
4. 如何联系你。

本次根据简历整理了以下结构：

| 网页区域 | 使用的资料                                     |
| -------- | ---------------------------------------------- |
| 首屏     | 姓名、基础设施与运维方向                       |
| 经历速览 | 2009 年职业起点、曾管理 300 台服务器、两项认证 |
| 关于我   | 网络、金融、云计算、自动化交付的职业发展       |
| 技术能力 | 系统自动化、容器交付、可观测与 AI 基础设施     |
| 工作经历 | 近期经历详细呈现，更早经历通过折叠区展示       |
| 教育     | 西安邮电大学、通信工程、本科及就读时间         |
| 联系方式 | 邮箱与 GitHub                                  |

原简历里的手机号、年龄、性别、民族没有放到网站中，原始简历也没有加入公开仓库。没有编造项目、客户评价或提升百分比。首屏终端和基础设施图只是工作方式示意，没有接入真实生产系统。

## 4. 创建文件并理解 HTML

主页必须有入口文件 `index.html`。Pages 访问站点目录时会寻找入口页面。

HTML 基本结构：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>施超的个人主页</title>
    <link rel="stylesheet" href="./assets/style.css" />
    <script src="./assets/main.js" defer></script>
  </head>
  <body>
    <header>导航</header>
    <main>个人介绍、技能和经历</main>
    <footer>页脚</footer>
  </body>
</html>
```

- `lang="zh-CN"`：告诉浏览器和辅助阅读工具，页面是中文。
- `UTF-8`：保证中文编码正确。
- `viewport`：让手机按设备宽度显示，配合 CSS 做适配。
- `title`：浏览器标签页标题。
- `defer`：让脚本等 HTML 解析完成后执行，避免找不到页面按钮。
- `header/main/footer`：给内容清晰的语义与结构。

### 页面内导航怎么做

```html
<a href="#experience">工作经历</a>
<section id="experience">这里是工作经历内容</section>
```

`href="#experience"` 指向同一页面中的 `id="experience"`。点击链接会滚动到对应区块，适合单页个人主页。

### 为什么资源路径写成 `./assets/...`

你的个人主页在 `/mynote/personal_homepage/` 子目录中：

```text
正确：./assets/style.css → /mynote/personal_homepage/assets/style.css
错误：/assets/style.css  → /assets/style.css
```

以 `/` 开头会从域名根目录开始寻找，容易造成“本地正常，发布后没有样式”。这个站点统一采用相对路径，因此也能直接双击查看。

## 5. 用 CSS 设计外观

本次采用深绿黑背景、浅色文字、绿色强调色，搭配终端与基础设施示意图。图形由 SVG 和 CSS 绘制，不需要外部图片服务和在线字体。

CSS 开头集中定义了变量：

```css
:root {
  --bg: #101716;
  --text: #e9ede5;
  --green: #bcf28b;
  --width: 1160px;
}
```

如果想把绿色改成蓝色，可以先只改 `--green`，刷新观察效果。`--bg` 是背景，`--text` 是主要文字颜色。

布局用到两种常见方式：

```css
/* 首屏：文字与示意图分成两列。 */
.hero {
  display: grid;
  grid-template-columns: 1.14fr 1fr;
}

/* 按钮、导航等较简单的横向排列。 */
.hero-actions {
  display: flex;
  align-items: center;
}
```

手机屏幕较窄，使用媒体查询切换为单列：

```css
@media (max-width: 760px) {
  .hero {
    grid-template-columns: 1fr;
  }
}
```

还添加了键盘焦点样式、跳转正文入口，以及 `prefers-reduced-motion` 支持。用户要求减少动态效果时，会关闭平滑滚动和过渡。

## 6. 用少量 JavaScript 增强交互

页面的大部分内容无需 JavaScript。即便脚本未执行，也能阅读经历、展开更早经历和通过邮箱链接联系。

复制邮箱的关键逻辑：

```js
await navigator.clipboard.writeText("shichao0503@163.com");
```

浏览器对剪贴板有权限限制：HTTPS 或 localhost 下通常可以使用；如果拒绝访问，脚本会显示手动复制提示，不会让按钮点击后毫无反馈。

展开更早经历用的是 HTML 原生组件：

```html
<details>
  <summary>更早的经历</summary>
  <p>放早期工作内容。</p>
</details>
```

它本身支持点击和键盘操作，不需要自己写一套折叠逻辑。

## 7. 本地预览

### 方式 A：直接双击

在项目文件夹里双击 `index.html`。适合快速查看文字和样式。

### 方式 B：启动 HTTP 服务

先确保安装了 Node.js。在 PowerShell 中执行：

```powershell
cd E:\Code\test\mynote\personal_homepage
node scripts/serve.mjs
```

看到下面输出说明服务已启动：

```text
Local: http://127.0.0.1:4321/mynote/personal_homepage/
```

打开这个网址。修改文件后刷新页面，预览服务不会自动刷新浏览器。按 `Ctrl+C` 停止服务。

也可以在仓库根目录执行 `node personal_homepage/scripts/serve.mjs`。脚本从自身所在位置计算仓库路径，所以两种启动方式都能正确预览。

`127.0.0.1` 只代表你自己的电脑；这个地址不能发给朋友作为公网网站。脚本只在本地回环地址监听，不需要开放公网端口。

如果端口被占用，可以在 PowerShell 中执行：

```powershell
$env:PORT = '4322'
node scripts/serve.mjs
```

## 8. 检查网站

发布前至少手动检查这些实际行为：

- 首页文字、学校、公司、日期与简历相符。
- 导航和首屏按钮能滚动到对应区域。
- 更早经历可以展开、收起。
- GitHub 链接指向自己的账号。
- 邮箱链接是 `mailto:`，点击后由电脑上的邮件客户端处理；这不是服务器发信。
- 复制按钮成功时给出提示，受限时提示手动复制。
- 手机宽度下没有横向滚动、文字遮挡或按钮挤压。
- HTML、CSS、JS、图标通过 HTTP 正常加载。

可以按浏览器 `F12`，在 Console 看脚本报错，在 Network 看有没有红色的 404 请求。本站没有登录、留言表单、数据库或访问统计。

## 9. 把文件提交到 GitHub

日常你可以使用 Git 命令。首次在自己的电脑拉取：

```powershell
cd E:\Code\test
git clone https://github.com/shichao0503/mynote.git
cd mynote
```

如果项目文件夹已经存在，不要在同一位置重复 clone。可以直接打开现有 Git 仓库；如果它只是下载的文件夹，先将它改名备份，再 clone，把需要修改的文件复制到克隆出的目录。

修改完成后：

```powershell
git status
git diff
git add personal_homepage index.html README.md .gitignore .nojekyll
git commit -m "Update personal homepage"
git push origin main
```

- `status`：看哪些文件改了。
- `diff`：看具体改动。
- `add`：选定要放入本次版本的文件。
- `commit`：生成本地版本记录。
- `push`：把本地提交同步到 GitHub。

如果 Git 尚未配置作者身份，按提示设置你自己的名称和邮箱。GitHub 网页登录和 Git 命令行认证是两套入口；电脑上的 Git 可能需要单独完成正常登录。不要把令牌写入代码或远程仓库地址。

这次命令行拉取遇到 TLS 连接问题，因此实际上传使用了已连接的 GitHub 工具，完成了相同目的的树对象、提交和分支更新。不是通过关闭证书校验来解决问题。

## 10. 开启 GitHub Pages

本仓库已按下面步骤配置完成，首次 Pages 发布工作流已成功。你无需重复设置，可用这些步骤理解发布过程或创建另一个网站。

打开仓库设置：<https://github.com/shichao0503/mynote/settings/pages>。

选择：

```text
Build and deployment
  Source: Deploy from a branch
  Branch: main
  Folder: / (root)
```

点击 **Save**。到仓库 **Actions** 中查看 Pages 部署进度，成功后访问：

<https://shichao0503.github.io/mynote/personal_homepage/>

这里继续选择仓库根目录：根目录 `index.html` 是旧地址跳转入口，实际个人主页是 `personal_homepage/index.html`，教程位于 `personal_homepage/docs/`。GitHub Pages 的分支发布目录仅支持根目录或 `/docs`，不需要把发布目录改为 `personal_homepage`。

根目录的 `.nojekyll` 文件告诉 Pages 把内容作为普通静态文件处理。本版不用自己维护 `.github/workflows/deploy.yml`；GitHub 仍会通过它管理的 Pages 工作流完成发布。启用一次后，后续提交到 `main` 会自动更新页面。

这一点与朋友的 Astro 项目不同：Astro 需要自定义安装与构建步骤，所以通常选择 **GitHub Actions** 作为发布源。不要把两套配置混用。

## 11. 以后怎么改

### 改介绍

打开 `index.html`，搜索“你好，我是施超”或需要修改的文字，直接替换标签里的内容。尽量保留标签、引号和区块 `id`。

### 新增工作经历

在 `.timeline` 中复制一个 `<article class="timeline-item">...</article>`，修改日期、职位、公司和职责。新工作放最前面；原来的“至今”和“当前”标记也要同步调整。

### 修改邮箱

同时修改：

1. `index.html` 中的可见邮箱文字与 `mailto:` 链接。
2. `assets/main.js` 中 `email` 的值。

### 新增学习笔记

第一步可以在 GitHub 中建立 `notes/` 文件夹存 Markdown，再从主页链接到 GitHub 文件。只上传 `.md` 并不会自动生成与首页一致的文章排版。

当笔记数量增加，再考虑 Astro：建立共享布局，使用 Markdown 写文章，构建输出到 `dist/`，用 Actions 自动发布。不要为了第一张介绍页先承担整套框架的学习成本。

## 12. 常见问题

| 现象               | 先检查什么                                                  |
| ------------------ | ----------------------------------------------------------- |
| 网站 404           | Pages 是否启用，是否选择 main 和根目录，Actions 是否成功    |
| 页面没有样式       | 资源是否提交，路径是否为 `./assets/...`，浏览器是否缓存旧版 |
| 提交后没有马上更新 | Actions 是否还在部署，是否提交到了正确分支                  |
| 邮箱复制失败       | 浏览器权限或访问方式，页面已提供手动复制提示                |
| 点击邮箱没反应     | 电脑是否设置默认邮件客户端，也可以直接复制邮箱              |
| 本地服务启动失败   | Node.js 是否安装，4321 是否已被占用                         |
| 中文乱码           | 文件是否使用 UTF-8 保存，页面是否保留 charset 声明          |

GitHub Pages 托管静态页面，不能直接在上面运行 Python、Java 或数据库服务。但浏览器中的 JavaScript 仍可以提供交互，这和“静态”并不矛盾。

## 13. 一个适合入门的练习顺序

1. 改一句个人介绍，刷新观察。
2. 改 `--green`，理解 CSS 变量。
3. 加一个技能标签，理解 HTML 列表。
4. 新增一个区块，再给导航加一个锚点链接。
5. 提交并 push，观察 Actions 与线上网站更新。

做完这几步，你就完整走过了“内容 → 页面 → 版本控制 → 自动发布”的流程。
